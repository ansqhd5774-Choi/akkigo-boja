# 삼국지 공개 글 오류 원인 및 개선 대책

상태: R2 DOM 검사·기존 글 변경 감지·공유 복구 구현 및 테마 공개 적용 완료. 삼국지·메이플·무한의 계단 기존 글 LIVE 갱신 확인 완료.

## 확인된 원인

1. 삼국지 원고는 compact-r1이다. R2 적용 때 data/article-presentation-r1-existing.json에 이 글을 예외로 포함시켜 구조 검사에서 빠졌다. 이는 전환 설계의 누락이다.
2. 안내 summary의 실제 문자열은 `ⓘ 날짜·검증 안내`이다. 공통 CSS의 44px 아이콘 영역에 긴 글자가 들어가 줄바꿈된다. 안내가 article 바로 아래에 있어 section 또는 ncp-brief의 위치 계약에도 맞지 않는다.
3. 현재 검사는 클래스·마커·코드 일치 및 일부 정규식만 검사한다. 안내 SVG, 소속 컨테이너, SEO 문구 노출, 실제 요약 요소와 숨긴 행 개수까지 확인하지 않는다.
4. 공유 코드는 navigator.share가 존재하면 호출한다. AbortError 외 오류는 모두 동일한 공유 실패로 표시하고, 오류 분류와 대체 경로를 제공하지 않는다. 분석 당시 예외명은 미수집이었다. 적용 후 실제 NotAllowedError를 확인했다. 브라우저가 해당 공유 요청을 허용하지 않은 것은 확인됐지만 구체적인 OS·정책 원인은 확정하지 않았다.
5. 68px는 원고 내부 CSS 값이다. 공개 공통 CSS는 PC 최소 76px와 모바일 가변 높이를 사용한다. 작성 결과 보고가 실제 적용 규칙과 분리됐다.

## 적용 순서

1. 삼국지 기존 postId 6539568622434094992와 URL을 유지하며 R2로 전환한다. 메뉴와 11개 코드·공유·복사 값은 유지한다. 긴 출처 설명을 section 안내로 옮기고, 상단 안내를 ncp-brief 안에 둔다. 검색 키워드·해시태그 나열은 방문자 본문에서 제거한다.
2. renderArticleInfo와 공통 CSS를 사용한다. 제목과 SVG 안내 아이콘은 같은 행에 둔다. 글별 위치·크기 CSS 추가로 해결하지 않는다. 5개를 넘는 목록은 정확히 5개 뒤부터 native details로 접는다. 삼국지의 현재 최대 목록은 5개이므로 불필요한 접기 버튼을 만들지 않는다.
3. 삼국지 R1 예외를 제거한다. 신규 또는 내용이 갱신된 게임 글에는 R2를 요구하고, 변경하지 않은 기존 글의 유예를 무조건 새 발행에 재사용하지 않는다.
4. 공유는 canShare가 제공될 때 payload를 사전 확인한다. 취소는 정상 취소로 처리한다. native share 실패 시 별도 사용자 클릭으로 실행하는 공유 링크 복사 경로를 제시한다. 성공·취소·다음 시도에서 이전 실패 안내를 정리한다. 진단에는 예외명과 단계만 기록하고 민감정보는 남기지 않는다.
5. 실제 예외명을 먼저 확보한 후 환경 문제와 코드 결함을 구분한다. 복사 완료 표시와 실제 클립보드 값 확인도 별도 결과로 보고한다. 빈 조회값만으로 클립보드 쓰기 실패를 단정하지 않는다.

## 재발 방지 및 완료 조건

- Verify와 발행 전 검사 모두 동일한 구조 검사 함수를 사용한다. SHA 검사 재사용과 무관하게 발행 직전 검사는 유지한다. 실제 발행·D1 변경 순서는 보존하고 cancel-in-progress:false를 유지한다.
- HTML을 DOM 구조로 검사하여 안내의 부모 위치, SVG·접근성 이름, 목록 disclosure의 위치와 남은 개수, 코드 보존을 확인한다. 가짜 클래스 하나만 넣어 통과하지 못하게 한다.
- 실패 fixture: R1 갱신, 긴 문자열 아이콘, 루트 안내, 노출된 출처 설명, SEO 키워드 나열, 6개 이상 미접기 목록, 불일치 공유 코드.
- 공유 fixture: 미지원, canShare=false, 성공, AbortError, NotAllowedError, 기타 실패, 링크 복사 실패, 실패 후 재시도 성공. 실패 안내와 버튼 복구를 각각 검사한다.
- UI 변경에 한해 공개 PC 863px·모바일 390px 검사: 안내 중심 높이 차이 0px, 공유 44px, 가로 넘침 없음, 안내·접기 열기/닫기 정상. 정상 콘텐츠 발행마다 화면 검사를 추가하지 않는다.
- 발행 완료는 Actions 성공 + Blogger LIVE + 기존 postId/URL 보존으로 판단한다. 디자인·복사·공유 증거는 별도로 보고한다. 행 높이는 고정 68px로 보고하지 않고 실제 공통 CSS의 PC 최소 76px·모바일 가변 규칙을 사용한다.
