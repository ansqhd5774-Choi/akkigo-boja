## 실행 순서와 완료 기준
1. **노출·영향 매핑(P0)**: 실패50URL와 본문 검증이 없는202 3URL를 공개77글/관련 쿠폰/최신 노출/대상 주장에 연결. 중복 URL 대신 영향받은 최신 주장 수로 우선순위 지정. 완료: 대상 또는 공개 미사용 상태를 전건 기록.
2. **404 2URL 복구(P0)**: 이동 원문 → 동일 공지 공식 원문 → 독립적 동일 주장 근거 → 날짜가 맞는 보존본 순서로 확인. 완료: 새 주소의 본문·코드·보상·조건·기간 동일성을 확인하고 기존 URL·교체 사유 유지. 실패: 미확인 표시에 전환, 최초 증거 기록 보존.
3. **도메인 장애 처리(P0)**: 522/530을 삭제로 단정하지 않음. 같은 도메인 대표1URL 관찰, 백오프·호스트별 동시1 제한. 권장 재관찰24시간 후 및72시간 후, 이후 주간. 실제 예약은 별도 구현·실행 증거 필요.
4. **제한19/미확인3/202 3(P0)**: 공식 사용자 브라우저에서 실제 본문 확인. 제한 우회 금지. 일반 브라우저 정상이라면 자동 조회 제한으로 기록. 확인 불가하면 대체 공식 근거 검토.
5. **최신 주장 정비(P0)**: 현재 사용 가능·보상·만료·서버·계정 조건의 유일한 근거가 사라지면 해당 주장만 미확인으로 낮춤. 기록 전체 삭제 또는 접속 실패=만료 처리 금지. 다른 유효한 근거가 있으면 해당 근거로 유지.
6. **501기록 보완(P1)**: 최신 후보 우선, 이후 이용량·수정 우선순위가 높은 기존 글, 마지막 과거 기록. 완료: 코드와 실제 원문 연결 또는 원문 미확인 명시. 숫자를 줄이기 위한 임의 연결 금지.
7. **근거 원장(P1)**: sourceId,원 URL,최종 URL,제목·발행자·원문 게시일,최종 접근일,최종 내용 확인일,보존 URL/보존일,본문 hash,주장 연결,근거 유형,상태,다음 검토일·교체 이력. 기존 모듈·데이터를 확장하고 별도 중복 DB는 만들지 않음.
8. **3가지 상태 분리(P1)**: 접근 상태 / 주장 확인 상태 / 계정 입력 성공 상태. HTTP200 또는 다른 목록에 존재하는 것으로 실사용 성공 표시 금지.
9. **화면(P1)**: 기존 출처 안내에서 공식/제3자/과거 보존본·마지막 내용 확인일·원문 접근 상태 표시. 테이블 열 추가·불필요한 화면 재설계 없이 해당 코드 문맥에서 제공.
10. **발행 검사(P1)**: 이번 신규·변경 내용의 핵심 주장에 연결된 확인된 근거 또는 정확한 미확인 표시 필수. 공식 등록 버튼이 확인된404/무관 페이지면 해당 발행 보류. 과거 참고 출처의 일시 오류는 경고·복구 큐로 분리하여 사이트 전체 발행을 막지 않음.
11. **내용 검사(P1)**: 200 오류화면/soft404/코드 소실/다른 게임/챌린지/도메인 재사용/예상 밖 이동 감지. 근거가 변경되면 수정 후보로 등록, 자동 사실 변경 금지. 개인정보·원문 전체 보관 금지; 필요한 최소 메타·검증 발췌만 권리 범위 내 보존.
12. **운영(P2)**: 최신·기간 민감 근거 일간,일반 주간,과거 월간은 제안 주기. 비용·레이트 제한 및 checkpoint 재사용. 지표는 최신 주장 근거 공백,노출된404,단일 장애 도메인 의존,기한 초과 미확인,복구 소요 시간. 경고 개수나HTTP성공률만으로 품질/SEO성과 판정하지 않음.

## 적용 원칙
같은 주장을 확인하지 않은 다른 홈페이지/검색결과로 대체하지 않는다. 다른 사이트의 반복 인용을 독립 출처 다수로 세지 않는다. 출처 부족을 nofollow/noindex 또는 기록 삭제로 해결하지 않는다. 실제 변경 후 기존 postId/URL 보존,공개 본문과 출처 링크·표시 PC/모바일 검증,원장 갱신까지 확인해야 해결 완료다.
