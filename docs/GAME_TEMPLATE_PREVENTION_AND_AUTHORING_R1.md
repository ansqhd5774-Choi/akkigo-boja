# 게임 글 양식 재발 방지 및 작성 시간 개선 R1

상태: 공통 렌더러·CSS·게임 글 전체/허브 검사 연결 구현. 작성 명세는 [GAME_PERIOD_AUTHORING_R1.md](GAME_PERIOD_AUTHORING_R1.md)를 따른다. 공개 갱신 상태는 실제 발행 증거로 별도 기록한다.
기준: 2026-10-09 사용자 확정 지시. 기간 탭 `최신 | 2026 | 2025 | 2024`를 사용한다.

## 확인된 원인

- 최종 양식이 버전이 있는 공통 작성 계약으로 저장되지 않았다. 게시 시스템은 각 원고의 HTML을 그대로 발행한다.
- `tools/validate-article-draft.mjs`는 애니모에 현재/만료/입력방법 탭을 강제한다. 사용자 확정 기간 탭과 충돌한다.
- 운영 지침 8B 및 `src/game-coupon-monthly.js`는 모든 월별 목록을 펼치도록 한다. 기간 탭으로 교체하면 기존 검사가 거부할 수 있다.
- 월별 검사는 `source.gameCouponTimeline`이 없는 글을 통과시킨다. 다른 양식으로 작성해도 공통 양식 위반을 검출하지 못한다.
- `tools/game-coupon-components.mjs`와 `src/game-coupon-table.js`에 테이블 생성기가 중복되어 있다. 원고별 HTML/CSS 작성과 게임별 검사가 남아 있다.

원인은 작성 지시·검사 계약의 불일치다. Blogger의 임의 레이아웃 변환으로 확인된 현상은 아니다.

## 현재 소스 점검

`node tools/audit-game-template.mjs`는 읽기 전용이다. 분류는 HTML 마커로 구조를 식별하며, 정상 작동이나 사용 가능 쿠폰 개수를 판정하지 않는다.

2026-10-09 실행: 게임 원고 30개 중 기간 탭 1개, 애니모 내용 탭 1개, 섹션형 28개. 과거 글을 포함한 재고 수치이며 전부 신규 규칙 위반이라는 의미는 아니다.

## 재발 방지 구현 순서

1. 단일 계약 `game-period-tabs-r1`과 공통 렌더러를 만든다. 기간 탭 외에 쿠폰/만료/입력방법 탭을 추가하지 않는다. 입력 방법·FAQ·출처는 탭 밖에 둔다.
2. `최신`에 보여줄 코드와 연도별 기록을 데이터로 구분한다. 최초 발견 월과 만료일은 별도 필드이며, 모르는 날짜는 null로 둔다. 날짜를 현재 연도로 추정하지 않는다. 연도 미상 이력은 탭 외 별도 기록으로 보존한다.
3. 코드 하나의 복사 버튼은 한 번만 생성한다. 최신과 연도 탭에 같은 코드를 중복 출력하는 방식은 기존 중복 검사와 충돌하므로 공유 행을 전환하거나 최신 코드의 연도 이력 중복 표시를 피하는 방식을 먼저 확정한다.
4. 기존 `src/game-coupon-table.js`를 재사용한다. 글마다 CSS·버튼을 다시 작성하지 않는다. 다른 생성기는 호출부를 조사한 뒤 하나로 통합한다.
5. 새 글에는 계약 버전을 필수로 넣는다. 버전·기간 탭·기본 최신 선택·라벨/패널 연결·중복 ID·모든 코드와 복사 값의 일치·역사 보존을 검사한다. 잘못된 양식은 발행 요청 전에 차단한다.
6. 애니모 전용 탭 검사와 월별 펼침 규칙을 새 계약으로 함께 바꾼다. 출처·보상·코드 검사는 유지한다. 기존 원고는 명시적 전환 목록으로 처리하여 무관한 발행을 갑자기 차단하지 않는다.
7. 기간 탭 클릭 및 키보드, PC·모바일 렌더링을 공통 양식에 한 번 검증한다. 이후 데이터만 바뀌면 정적 검사와 LIVE/URL 검증을 수행한다. UI 변경·실패 때만 화면 검사를 추가한다.

완료 조건: 새 글이 공통 생성 명령만으로 만들어지고, 잘못된 탭을 넣은 회귀 fixture가 거부되며, 전환한 글의 기존 postId·URL·전체 기록이 보존되어야 한다. 문서 저장만으로 이 조건을 충족했다고 보고하지 않는다.

## 작성 시간 개선

목표 흐름: 자료 조사 → 구조화 코드 데이터 갱신 → 단일 생성 명령 → 변경 범위 검사 → 동일 SHA 검증 재사용 → 기존 글 갱신 → LIVE·URL 확인.

- 반복 HTML/CSS 작성, 코드 개수 수기 계산, 게임별 검사 추가를 없앤다.
- 기존 최초 발견 시점·이력을 병합하고 후보/만료 판단은 근거 데이터로 처리한다. 빠르게 작성하기 위해 검증이나 실패 탐지를 삭제하지 않는다.
- 생성한 원고와 카탈로그를 각각 손으로 수정하지 않는다. 생성 산출물과 입력의 해시를 기록하고 차이가 나면 실패시킨다.
- 검증 재사용은 정확한 커밋 SHA가 같을 때만 허용한다. 발행·DB 변경의 순서와 취소 방지 규칙을 유지한다.

실측: 이 PC에서 기존 공통 테이블 생성기로 163행을 100회 생성했을 때 중앙값 0.509ms, P95 1.666ms. 이는 테이블 문자열 생성만의 비용이다. 조사·원고 작성·테스트·발행 시간이나 개선 전후 절감률이 아니다.

효과 산출 방법: 전환 전후 각각 실제 글 작성 시 조사/데이터 입력/레이아웃/검사/발행 시간을 기록한다. 비교 가능한 코드 수·자료 난도의 글을 사용한다. `총 절감 시간 = 전환 전 단계별 시간 합 - 전환 후 합`으로 계산한다. 현재는 전체 작성 시간 기준값이 없어 분 단위 절감이나 속도 향상률을 확정할 수 없다.

## 적용 범위

이번 수립 작업은 운영 게시물·Worker·D1·티스토리 러너를 변경하지 않는다. 다음 구현은 공통 생성기·검사 연결부터 진행하고, 전환 원고별 데이터/URL 보존을 확인한 뒤 공개 갱신한다.
